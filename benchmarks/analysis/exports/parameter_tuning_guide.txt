════════════════════════════════════════════════════════════════════════════════════

PARAMETER CHOICE: D vs M(K)
───────────────────────────

For DMCFA/DMCFAE: D and M(K) are EQUALLY EFFECTIVE
  • Both improve the same examples
  • Neither is inherently superior
  • Choose based on convenience, not effectiveness

For KCFA: Only K parameter available
  • Use K=4-6 for balanced cost/benefit
  • Higher K (7-10) has exponential cost
  • Consider using DMCFA/DMCFAE as alternative

════════════════════════════════════════════════════════════════════════════════════

ALGORITHM CHOICE
────────────────

DMCFA (Baseline)
  • Fast baseline
  • ~86% average precision
  • Good for: basic, nested, multi-effect (already perfect)
  • Use for: Most general-purpose analysis

DMCFAE (Exponential variant)
  • ~50% slower than DMCFA
  • Better on state-handler (76.7% vs 63.3%)
  • Use for: When state-handler precision is critical

KCFA (k-CFA)
  • 3-10x slower than DMCFA
  • Excellent on simple patterns (100% precision)
  • Poor on nondeterminism (0-65% precision)
  • Use for: Specific patterns that need classical k-CFA

════════════════════════════════════════════════════════════════════════════════════

TUNING DECISION TREE
────────────────────

1. Measure precision at baseline (D=0/1, M(K)=1, K=1)
   
   ├─ If 100% precision → STOP! Don't tune parameters
   │                      (Examples: basic, nested)
   │
   ├─ If 0% precision → Try different algorithm
   │                    (Example: KCFA on state-handler)
   │
   └─ If 50-95% precision → Selective tuning
                            Check if examples improve with higher sensitivity
                            If yes: tune (D+2, M(K)+2)
                            If no: you've hit the ceiling

2. Measure cost of increased sensitivity
   
   ├─ < 1.5x cost → Consider tuning for 5%+ precision gain
   └─ > 2.0x cost → Only tune if precision improvement is critical
