# Sensitivity Parameter Analysis - Graphs and Insights

This document describes the generated comparison graphs for analyzing how different analysis types scale with changes in sensitivity parameters (D, M(K), and K).

## Graph Generation

All graphs are generated by `generate-comparison-graphs.py` and saved to `benchmarks/analysis/graphs/`.

```bash
python3 generate-comparison-graphs.py
```

## Graph Types

### Per-Benchmark Analysis

For each of the 8 benchmarks, three graphs are generated:

#### 1. D Comparison (`{benchmark}_d_comparison.png`)
**Purpose**: Show how demand-level sensitivity affects execution time for different DMCFA variants.

- **X-axis**: D (demand level, typically 1-4)
- **Y-axis**: Execution time in seconds
- **Lines**: 
  - DMCFA (solid line, blue)
  - DMCFA-Exp (solid line, pink/magenta)

**Key Insight**: D typically has minimal impact on execution time across all analyses. Most benchmarks show relatively flat lines, indicating D is not the dominant cost factor.

#### 2. M(K) Comparison (`{benchmark}_mk_comparison.png`)
**Purpose**: Compare context sensitivity costs across DMCFA analyses and KCFA.

- **X-axis**: M(K) or K (context sensitivity, typically 1-6 or 0-10)
- **Y-axis**: Execution time in seconds
- **Lines**:
  - DMCFA M(K) (solid line, blue, circles)
  - DMCFA-Exp M(K) (solid line, pink, circles)
  - KCFA K (dashed line, orange, squares)

**Key Insight**: M(K) has substantial impact, especially for:
- `complex-flow`: Dramatic exponential growth in time
- `nested-nondet`: Significant exponential growth
- `state-handler`: Moderate exponential growth
- `basic`, `nondet`, `nested`, `recursion`: Near-linear or moderate growth

#### 3. Precision vs Cost (`{benchmark}_precision_vs_cost.png`)
**Purpose**: Show the trade-off between time cost and context sensitivity level.

- **X-axis**: Context sensitivity parameter
- **Y-axis**: Execution time
- **Lines**: All available analyses for that benchmark

**Key Insight**: Different analyses scale differently. DMCFA-Exp often provides similar context precision with different time cost than DMCFA.

### Cross-Benchmark Summary Graphs

#### 1. `crossbench_d_cost.png`
**Purpose**: Show average D cost across the entire benchmark suite for each analysis type.

- **Layout**: Two side-by-side plots (DMCFA, DMCFA-Exp)
- **X-axis**: D value
- **Y-axis**: Average execution time across all 8 benchmarks
- **Line**: Single line showing average trend

**Key Insight**: D cost is consistently low and flat across the suite. This suggests D is not a primary driver of analysis complexity.

#### 2. `crossbench_mk_cost.png`
**Purpose**: Compare M(K)/K cost scaling across different analysis types.

- **Layout**: Two side-by-side plots
  - Left: DMCFA analyses with M(K)
  - Right: KCFA with K
- **X-axis**: M(K) or K value
- **Y-axis**: Average execution time
- **Lines**: 
  - DMCFA (blue circles)
  - DMCFA-Exp (pink circles)
  - KCFA (orange squares)

**Key Insight**: Shows how the two analysis families scale differently. KCFA and DMCFA-Exp may have different scaling characteristics.

## Analysis Interpretation Guide

### Reading the Graphs

**Flat or near-flat lines** (e.g., D in most benchmarks):
- Parameter has minimal impact on performance
- Safe to increase for better precision without major cost

**Linear growth** (e.g., M(K) in basic, nondet):
- Proportional cost increase with parameter
- Predictable scaling behavior

**Exponential growth** (e.g., M(K) in complex-flow, nested-nondet):
- Worst-case behavior with certain patterns
- Parameter should be used carefully
- May indicate hitting algorithmic complexity limits

**Step functions or discontinuities**:
- Parameter interacts with implementation-specific thresholds
- Careful tuning needed near these points

### Sensitivity Parameter Semantics

#### D (Demand Level)
- Controls how many demand values are tracked
- Lower D: fewer distinctions, faster analysis, less precise
- Higher D: more distinctions, slower analysis, more precise
- **Range**: Typically 1-4 for analysis; 0-10 for KCFA

#### M(K) (Continuation Approximation)
- Controls continuation/control context abstraction
- Lower M(K): coarser abstraction, faster analysis
- Higher M(K): finer abstraction, more precise analysis
- **Range**: Typically 1-6 for DMCFA analyses

#### K (KCFA Context Sensitivity)
- Traditional k-CFA parameter for KCFA analysis
- Lower K: simpler contexts, faster analysis
- Higher K: more contexts, more precise analysis
- **Range**: Typically 0-10

### Comparing Analyses

**DMCFA vs DMCFA-Exp vs KCFA**:
- DMCFA: Baseline dynamic analysis
- DMCFA-Exp: Experimental variant with different trade-offs
- KCFA: Traditional context-sensitive analysis

Direct M(K) to K comparison:
- M(K)=1 approximately equals K=2
- M(K)=2 approximately equals K=3
- M(K)=3 approximately equals K=4
- Etc.

## Benchmark-Specific Observations

### Fast Benchmarks (D and M(K) cost minimal)
- **basic**: Constant time ~0.002s, perfect precision
- **nondet**: Linear growth, 86.7% precision
- **nested**: Flat D, linear M(K), 100% precision
- **recursion**: Low cost, 92.6% precision

### Complex Benchmarks (D impact low, M(K) impact high)
- **complex-flow**: M(K) shows up to 152x time increase
- **nested-nondet**: M(K) shows up to 31x time increase
- **state-handler**: M(K) shows up to 4x time increase

### Precision Patterns
- 100% precision: basic, nested
- 85-95% precision: nondet, recursion, multi-effect, complex-flow
- <85% precision: state-handler, nested-nondet

## Practical Recommendations

### For Production Analysis
1. Use **D=2-3**: Minimal cost increase, reasonable precision gains
2. Use **M(K)=2-3**: Good balance of precision and performance
3. Monitor complex-flow and nested-nondet for exponential growth

### For Research/Exploration
1. Vary D to see impact on precision
2. Sweep M(K) values to find diminishing returns
3. Compare DMCFA vs DMCFA-Exp for experimental validation

### For Approximation
1. If time-constrained, use **D=1, M(K)=1**
2. If more precision needed and time permits, increase **M(K)** first
3. Increase **D** only after saturating M(K) gains

## Generating Custom Graphs

To modify graph generation or add new analyses:

1. Edit `generate-comparison-graphs.py`
2. Modify colors, markers, or analysis selections
3. Run: `python3 generate-comparison-graphs.py`

Key customization points:
- `DMCFA_ANALYSES`: Add/remove analysis types
- `colors`: Customize color scheme
- Plot functions: Add new graph types
- `SUITE_FILES`: Include/exclude specific benchmarks
